Create temporary inboxes, check incoming email, and download attachments from your own scripts and apps.

BASE URLhttps://mail.example.com

Use the address of your TMailSharp website. All paths below are relative to it. The mailbox API receives email; it cannot send or reply.

Get your first inbox

Create an account or sign in, then open API keys in the sidebar. Confirm your password to create a named key, and copy it before leaving the page.

Bash / curl
BASE_URL='https://mail.example.com'
export TMAIL_API_KEY='YOUR_API_KEY'

# Every API request needs your account's bearer key.
curl --fail-with-body -sS -H "Authorization: Bearer $TMAIL_API_KEY" \
  "$BASE_URL/api/bootstrap"

# Create a temporary inbox with a random address.
curl --fail-with-body -sS -H "Authorization: Bearer $TMAIL_API_KEY" \
  -H 'Content-Type: application/json' -d '{}' \
  "$BASE_URL/api/mailboxes"

# Copy the returned id, then check for messages.
MAILBOX_ID='PASTE_MAILBOX_ID'
curl --fail-with-body -sS -H "Authorization: Bearer $TMAIL_API_KEY" \
  "$BASE_URL/api/mailboxes/$MAILBOX_ID/messages"

Send an email to the returned address from your usual mail client, then check for messages. Keys for the same account access the same inboxes. Use permanent: true in the creation body to keep the address.

Example creation response · 201 Created
{
  "id": "9e892f5b55964e9d8200954659582913",
  "address": "quiet.otter.4829@inbox.example.com",
  "domain": "inbox.example.com",
  "createdAt": "2026-10-29T10:00:00Z",
  "expiresAt": "2026-10-29T11:00:00Z",
  "isPermanent": false
}
Server-side JavaScript example

Run this on your server with the key in its secret settings. Do not embed an API key in public browser JavaScript.

Node.js / fetch
const baseUrl = 'https://mail.example.com';
const apiKey = process.env.TMAIL_API_KEY;
if (!apiKey) throw new Error('Set TMAIL_API_KEY in your secret settings.');
const headers = {
  Authorization: 'Bearer ' + apiKey,
  'Content-Type': 'application/json'
};
const created = await fetch(baseUrl + '/api/mailboxes', {
  method: 'POST', headers, body: JSON.stringify({})
});
const inbox = await created.json();
if (!created.ok) throw new Error(inbox.error || 'HTTP ' + created.status);

const response = await fetch(baseUrl + '/api/mailboxes/' + inbox.id + '/messages', { headers });
const result = await response.json();
if (!response.ok) throw new Error(result.error || 'HTTP ' + response.status);
console.log(inbox.address, result.messages);

API keys & requests

An account and API key are required.

Send Authorization: Bearer YOUR_API_KEY on every request. A browser session or an inbox ID cannot replace the key. You can only access mailboxes owned by the key's account.

  • Create and revoke keys under API keys. An account can have up to 10 active keys. Full keys are displayed once and stored only as hashes.
  • Revocation takes effect on the next request. Password and account-security changes invalidate existing keys; a locked account cannot use its keys.
  • Use HTTPS and keep keys in server-side secret settings. Never put a key in a URL, public code, browser storage, or a shared screenshot.
  • JSON bodies require Content-Type: application/json. Cookies, CSRF tokens, and X-TMail-Request are not required for the API.
  • Cross-origin browser access is not enabled. Use a server-side client when integrating another website.
  • API responses use Cache-Control: no-store. Dates are UTC strings. Treat IDs as opaque values.

Temporary inboxes expire at expiresAt. Permanent addresses have isPermanent: true and expiresAt: null. Messages have their own retention timer; reading a message never deletes it or restarts that timer.

Inboxes

GET/api/bootstrap

Get available email domains, the key owner’s active inboxes, and mailbox limits.

200 OK · Mailbox fields
{
  "domains": [
    { "name": "inbox.example.com", "enabled": true, "createdAt": "2026-10-29T09:00:00Z" }
  ],
  "mailboxes": [],
  "lifetimeMinutes": 60,
  "messageRetentionMinutes": 60,
  "maxMessageBytes": 5242880,
  "maxMailboxes": 25
}

mailboxes contains the same inbox objects returned on creation. The API does not return browser-session tokens or account roles. Domain-specific retention, when present, overrides messageRetentionMinutes.

POST/api/mailboxes

Create an inbox. Returns 201 Created, an inbox object, and a Location header identifying the inbox. Use /messages to list its mail; there is no GET endpoint at the bare inbox URL.

JSON request body
{ "localPart": "my-test-inbox", "domain": "inbox.example.com" }
Creation fields
FieldTypeBehavior
localPartstring or nullOptional. Omit, send null, or leave blank for a random name.
domainstring or nullOptional. Use an enabled domain from /api/bootstrap. If omitted, null, or blank, the first available domain is used.
permanentbooleanOptional; defaults to false. Set true to reserve an address permanently for your account.

Custom names are trimmed and lowercased. They must be 3–40 ASCII letters, digits, dots, underscores, or hyphens, starting and ending with a letter or digit. Consecutive dots and reserved address names are rejected.

A reserved address or a full account returns 409. Recently deleted or expired addresses can remain reserved; choose another name if needed.

DELETE/api/mailboxes/{id}

Delete an inbox owned by your account and all its messages and attachments. Returns 204 No Content. This cannot be undone and does not release its address reservation early.

Bash / curl · Uses the quickstart variables
curl --fail-with-body -sS -H "Authorization: Bearer $TMAIL_API_KEY" \
  -X DELETE \
  "$BASE_URL/api/mailboxes/$MAILBOX_ID"

POST/api/mailboxes/{id}/reserve

Keep one of your account’s temporary addresses permanently. Send your bearer key; no body is needed. Returns the updated inbox with isPermanent: true and expiresAt: null. Messages still expire on their retention schedule.

Messages & attachments

Use the inbox’s id for {id}, the message’s id for {messageId}, and an attachment’s id for {attachmentId}. Every request requires an API key belonging to the inbox owner.

GET/api/mailboxes/{id}/messages

Returns 200 OK with { "mailbox": { ... }, "messages": [ ... ] }. Messages are newest first, with no pagination. An inbox with no mail returns an empty array.

Example item in messages
{
  "id": "d547981cd15a418181675b53b60fc6cf",
  "sender": "hello@example.com",
  "senderName": "Example sender",
  "subject": "Your verification code",
  "preview": "Your code is 482 916.",
  "receivedAt": "2026-10-29T10:05:00Z",
  "isRead": false,
  "attachmentCount": 1
}

Summaries do not contain message bodies or attachment contents. Poll at a reasonable interval, such as every six seconds, and stop when a temporary inbox expires.

GET/api/mailboxes/{id}/messages/{messageId}

Read a message and mark it as read. Returns 200 OK with the following shape:

Example message detail
{
  "id": "d547981cd15a418181675b53b60fc6cf",
  "sender": "hello@example.com",
  "senderName": "Example sender",
  "recipient": "quiet.otter.4829@inbox.example.com",
  "subject": "Your verification code",
  "textBody": "Your code is 482 916.",
  "htmlBody": "<p>Your code is <strong>482 916</strong>.</p>",
  "receivedAt": "2026-10-29T10:05:00Z",
  "isRead": true,
  "attachments": [
    { "id": "48d75ef667da4dd1b325c7539ad5b925", "fileName": "hello.txt", "size": 52 }
  ]
}

htmlBody is sanitized; scripts, remote images, forms, and embedded content are removed. Render email in an isolated frame or show textBody as text. Attachment size is in bytes; file content comes from the download endpoint.

Bash / curl · Uses the quickstart variables
MESSAGE_ID='PASTE_MESSAGE_ID'
curl --fail-with-body -sS -H "Authorization: Bearer $TMAIL_API_KEY" \
  "$BASE_URL/api/mailboxes/$MAILBOX_ID/messages/$MESSAGE_ID"

GET/api/mailboxes/{id}/messages/{messageId}/content

Returns a complete HTML document with Content-Type: text/html; charset=utf-8 and a restrictive Content Security Policy. Fetch the HTML with your bearer key before rendering it in an isolated frame. Add ?theme=light for light styling; the default is dark. This endpoint does not mark the message as read.

GET/api/mailboxes/{id}/messages/{messageId}/attachments/{attachmentId}

Download a file. Returns binary bytes as application/octet-stream with Content-Disposition: attachment and the original filename. Attachment metadata and downloads are only available to the inbox owner.

Bash / curl · Uses the variables above
ATTACHMENT_ID='PASTE_ATTACHMENT_ID'
curl --fail-with-body -sS -H "Authorization: Bearer $TMAIL_API_KEY" \
  -o attachment.bin \
  "$BASE_URL/api/mailboxes/$MAILBOX_ID/messages/$MESSAGE_ID/attachments/$ATTACHMENT_ID"

DELETE/api/mailboxes/{id}/messages/{messageId}

Delete a message and its attachments from an owned inbox. Send your bearer key. Returns 204 No Content.

Errors & limits

Application errors return JSON with an error message. Check the HTTP status before using a response. Framework errors, including malformed JSON or unsupported content types, may have a different body or no body.

Example · 404 Not Found
{ "error": "This inbox has expired or is no longer available." }
HTTP status reference
StatusMeaning
200Request completed. The body is JSON, HTML, or file bytes, depending on the endpoint.
201Inbox created.
204Delete completed. There is no response body to parse.
400Invalid address, unavailable domain, or invalid body.
401Missing, invalid, revoked, or invalidated key, or an unavailable/locked account.
404Inbox expired, wrong account, or missing message or attachment.
409Address reserved or active inbox limit reached.
413 / 415Request body too large or unsupported content type.
429Too many requests from this IP. Wait up to one minute before retrying.
500Server error. Avoid repeatedly retrying inbox creation without checking your account’s inbox list.
503Address generation is temporarily unavailable.

Request limits

Requests are limited per client IP: most mailbox requests allow 180 per minute and inbox creation allows 12 per minute. On 429, wait up to one minute before trying again.

JSON request bodies are limited to 64 KiB. Check /api/bootstrap for the current inbox lifetime, active inbox limit, and incoming message size limit.
