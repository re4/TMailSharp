Create temporary inboxes, check incoming email, and download attachments from your own scripts and apps.

BASE URLhttps://mail.example.com

Use the address of your TMailSharp website. All paths below are relative to it. The mailbox API receives email; it cannot send or reply.

Get your first inbox

Create an inbox, keep the session cookie, then check for messages. An empty JSON object lets the server choose an available domain and a random address.

Bash / curl
BASE_URL='https://mail.example.com'
COOKIE_JAR='./tmail-cookies.txt'

# Create an inbox and save its access cookie.
curl -sS -c "$COOKIE_JAR" -b "$COOKIE_JAR" \
  -H 'X-TMail-Request: 1' \
  -H 'Content-Type: application/json' \
  -d '{}' \
  "$BASE_URL/api/mailboxes"

# Copy the id from the response above, then check its inbox.
MAILBOX_ID='PASTE_MAILBOX_ID'
curl -sS -c "$COOKIE_JAR" -b "$COOKIE_JAR" \
  "$BASE_URL/api/mailboxes/$MAILBOX_ID/messages"

Send an email to the returned address from your usual mail client, then check for messages. Keep using the same cookie file for every request.

Example creation response · 201 Created
{
  "id": "21fc2b180a734dc0939f8be8125c3d27",
  "address": "quiet.otter.4829@inbox.example.com",
  "domain": "inbox.example.com",
  "createdAt": "2026-10-29T10:00:00Z",
  "expiresAt": "2026-10-29T11:00:00Z"
}

IDs, domains, timestamps, and limits shown in examples are illustrative. Use the values returned by your server.

JavaScript example for a page on this server

Browser requests must use the same origin as TMailSharp. The browser stores the HttpOnly cookie automatically; JavaScript does not need to read it.

JavaScript / fetch
const created = await fetch('/api/mailboxes', {
  method: 'POST',
  credentials: 'same-origin',
  headers: {
    'Content-Type': 'application/json',
    'X-TMail-Request': '1'
  },
  body: JSON.stringify({})
});
const inbox = await created.json();
if (!created.ok) throw new Error(inbox.error || `HTTP ${created.status}`);

const response = await fetch(`/api/mailboxes/${inbox.id}/messages`, {
  credentials: 'same-origin'
});
const result = await response.json();
if (!response.ok) throw new Error(result.error || `HTTP ${response.status}`);
console.log(inbox.address, result.messages);

Sessions & requests

Your cookie is your inbox access.

Every API request uses the private tmailsharp.session cookie. The server creates one if it is missing. Losing it means losing access to your inboxes; an email address or inbox ID alone cannot recover them.

  • Persist cookies between requests. With curl, use both -c and -b with the same file. Keep that file private.
  • For POST, PUT, and DELETE, send X-TMail-Request: 1.
  • For JSON bodies, also send Content-Type: application/json.
  • If you send an Origin header, its scheme, host, and port must match the server. Cross-origin browser access is not enabled; use a server-side client for another website.
  • API responses use Cache-Control: no-store. Dates are UTC strings. Treat all IDs as opaque values.

Inboxes and their messages expire together at expiresAt. Expired inboxes immediately return 404, even before background storage cleanup finishes. Creating another inbox does not extend the lifetime of an existing one.

Inboxes

GET/api/bootstrap

Get available email domains, this session’s active inboxes, and mailbox limits. This is also a way to establish a session before creating an inbox.

200 OK · Mailbox fields
{
  "domains": [
    { "name": "inbox.example.com", "enabled": true, "createdAt": "2026-10-29T09:00:00Z" }
  ],
  "mailboxes": [],
  "lifetimeMinutes": 60,
  "maxMessageBytes": 5242880,
  "maxMailboxes": 10
}

Only mailbox-related fields are shown above; other response fields can be ignored. mailboxes contains the same inbox objects returned on creation. An empty domains array means no domains are currently available for new inboxes.

POST/api/mailboxes

Create an inbox. Returns 201 Created, an inbox object, and a Location header identifying the inbox. Use /messages to list its mail; there is no GET endpoint at the bare inbox URL.

JSON request body
{ "localPart": "my-test-inbox", "domain": "inbox.example.com" }
Creation fields
FieldTypeBehavior
localPartstring or nullOptional. Omit, send null, or leave blank for a random name.
domainstring or nullOptional. Use an enabled domain from /api/bootstrap. If omitted, null, or blank, the first available domain is used.

Custom names are trimmed and lowercased. They must be 3–40 ASCII letters, digits, dots, underscores, or hyphens, starting and ending with a letter or digit. Consecutive dots and reserved address names are rejected.

A reserved address or a full session returns 409. Recently deleted or expired addresses can remain reserved; choose another name if needed.

DELETE/api/mailboxes/{id}

Delete an inbox owned by this session and all its messages and attachments. Returns 204 No Content. This cannot be undone and does not release its address reservation early.

Bash / curl · Uses the quickstart variables
curl -sS -c "$COOKIE_JAR" -b "$COOKIE_JAR" \
  -X DELETE -H 'X-TMail-Request: 1' \
  "$BASE_URL/api/mailboxes/$MAILBOX_ID"

Messages & attachments

Use the inbox’s id for {id}, the message’s id for {messageId}, and an attachment’s id for {attachmentId}. Every request requires the owning session cookie.

GET/api/mailboxes/{id}/messages

Returns 200 OK with { "mailbox": { ... }, "messages": [ ... ] }. Messages are newest first, with no pagination. An inbox with no mail returns an empty array.

Example item in messages
{
  "id": "d547981cd15a418181675b53b60fc6cf",
  "sender": "hello@example.com",
  "senderName": "Example sender",
  "subject": "Your verification code",
  "preview": "Your code is 482 916.",
  "receivedAt": "2026-10-29T10:05:00Z",
  "isRead": false,
  "attachmentCount": 1
}

Summaries do not contain message bodies or attachment contents. Poll at a reasonable interval, such as every six seconds, and stop when the inbox expires.

GET/api/mailboxes/{id}/messages/{messageId}

Read a message and mark it as read. Returns 200 OK with the following shape:

Example message detail
{
  "id": "d547981cd15a418181675b53b60fc6cf",
  "sender": "hello@example.com",
  "senderName": "Example sender",
  "recipient": "quiet.otter.4829@inbox.example.com",
  "subject": "Your verification code",
  "textBody": "Your code is 482 916.",
  "htmlBody": "<p>Your code is <strong>482 916</strong>.</p>",
  "receivedAt": "2026-10-29T10:05:00Z",
  "isRead": true,
  "attachments": [
    { "id": "48d75ef667da4dd1b325c7539ad5b925", "fileName": "hello.txt", "size": 52 }
  ]
}

htmlBody is sanitized; scripts, remote images, forms, and embedded content are removed. Render email in an isolated frame or show textBody as text. Attachment size is in bytes; file content comes from the download endpoint.

Bash / curl · Uses the quickstart variables
MESSAGE_ID='PASTE_MESSAGE_ID'
curl -sS -c "$COOKIE_JAR" -b "$COOKIE_JAR" \
  "$BASE_URL/api/mailboxes/$MAILBOX_ID/messages/$MESSAGE_ID"

GET/api/mailboxes/{id}/messages/{messageId}/content

Returns a complete HTML document with Content-Type: text/html; charset=utf-8 and a restrictive Content Security Policy, suitable for a same-origin iframe. Add ?theme=light for light styling; the default is dark. This endpoint does not mark the message as read.

GET/api/mailboxes/{id}/messages/{messageId}/attachments/{attachmentId}

Download a file. Returns binary bytes as application/octet-stream with Content-Disposition: attachment and the original filename. Attachment metadata and downloads are only available to the inbox owner.

Bash / curl · Uses the variables above
ATTACHMENT_ID='PASTE_ATTACHMENT_ID'
curl --fail-with-body -sS -c "$COOKIE_JAR" -b "$COOKIE_JAR" \
  -o attachment.bin \
  "$BASE_URL/api/mailboxes/$MAILBOX_ID/messages/$MESSAGE_ID/attachments/$ATTACHMENT_ID"

DELETE/api/mailboxes/{id}/messages/{messageId}

Delete a message and its attachments from an owned inbox. Send X-TMail-Request: 1. Returns 204 No Content.

Errors & limits

Application errors return JSON with an error message. Check the HTTP status before using a response. Framework errors, including malformed JSON or unsupported content types, may have a different body or no body.

Example · 404 Not Found
{ "error": "This inbox has expired or is no longer available." }
HTTP status reference
StatusMeaning
200Request completed. The body is JSON, HTML, or file bytes, depending on the endpoint.
201Inbox created.
204Delete completed. There is no response body to parse.
400Invalid address, unavailable domain, or invalid request body.
403Missing X-TMail-Request: 1 or an Origin that does not match the server.
404Inbox expired, wrong session, or missing message or attachment.
409Address reserved or active inbox limit reached.
413 / 415Request body too large or unsupported content type.
429Too many requests from this IP. Wait up to one minute before retrying.
500Server error. Avoid repeatedly retrying inbox creation without checking your session’s inbox list.
503Address generation is temporarily unavailable.

Request limits

Requests are limited per client IP: most mailbox requests allow 180 per minute and inbox creation allows 12 per minute. On 429, wait up to one minute before trying again.

JSON request bodies are limited to 32 KiB. Check /api/bootstrap for the current inbox lifetime, active inbox limit, and incoming message size limit.
